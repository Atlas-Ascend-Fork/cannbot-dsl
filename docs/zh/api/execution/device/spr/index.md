# 特殊寄存器

特殊寄存器访问接口用于读取或设置设备的特殊寄存器。当前提供CTRL控制寄存器的读写接口。

## 接口

| 接口 | 说明 |
| --- | --- |
| [`get_ctrl`](get-ctrl.md) | 读取CTRL控制寄存器的完整64位值。 |
| [`set_ctrl`](set-ctrl.md) | 写入CTRL控制寄存器的完整64位值。 |

## CTRL读写与状态恢复

CTRL是控制设备计算行为的特殊寄存器，不是GM或UB中的普通数据。读取结果属于当前设备执行上下文；不能用Host端调用来查询，也不能假设不同核、子核或AIC/AIV上下文共享同一份值。

临时调整CTRL时，应遵循以下顺序：

1. 调用`get_ctrl()`保存当前值。
2. 仅修改需要调整的比特位，保留其他位和保留位，再调用`set_ctrl(value)`写回。
3. 执行依赖该配置的计算，并按相关接口的要求保证操作顺序。
4. 在同一设备执行上下文中显式恢复保存的值；存在异步计算或跨流水依赖时，需确保受影响的计算完成后再恢复。

如果期间还改变了其他需要保留的CTRL位，恢复时应重新读取当前值，仅恢复本次调整的目标位，避免直接写回旧的完整值而覆盖其他配置。两个接口本身不提供按位修改或自动恢复功能。

`set_ctrl`不会自动恢复CTRL配置，应在当前Kernel内显式保存和恢复需要临时调整的状态。

两个接口应在`@kernel`函数体或由其展开的设备侧辅助函数中调用，不在Host或`vf(...)`作用域内直接调用。需要影响VF计算时，在Kernel中先设置，再执行VF，并在满足执行顺序要求后恢复。

常用CTRL位及其不同极性见[`set_ctrl`参数说明](set-ctrl.md#参数说明)。

## 与转换接口饱和参数的关系

`vcast(..., saturate=...)`按其自身规则选择转换行为，不能视为全局CTRL配置的替代。

需要全局控制时，应显式读改写CTRL，并根据具体位的适用范围判断作用；例如CTRL[59]的转换饱和配置仅在CTRL[60]选择全局策略时生效。
