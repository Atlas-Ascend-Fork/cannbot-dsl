# 通用接口文档模板

本模板用于编写CANNBot-DSL公共接口文档，固定包括以下章节：产品支持情况/功能说明/函数原型/参数说明/返回值说明/约束说明/调用示例，且要求顺序固定，不得修改章节名称。

当接口无参数/无返回值/无约束等导致对应章节（如"参数说明"）无实际内容时，**章节节点必须保留**：标题不得省略或删除，正文内容写“无”。

## 产品支持情况

用于说明接口支持的硬件产品范围，产品名称和排列顺序保持统一。产品名称严格与模板一致，支持状态只写“支持”或“不支持，未经验证的产品不得标记为“支持”。

CANNBot-DSL从Ascend 950PR&950DT系列产品开始支持，为提升维护效率和减少冗余信息，历史产品型号不写，在文档开头统一声明一次即可。后续支持新产品后，按照从新到旧的顺序维护。

示例：

- Ascend 950PR&950DT系列产品：支持

## 功能说明

介绍接口使用场景和接口功能，通常控制在一至三句话。数学接口应使用公式明确说明覆盖、累加、广播或转置等行为，不写编译流程和内部调用关系，且变量名须与函数原型中的变量名一致。

昇腾领域的术语请参考[昇腾术语表](https://www.hiascend.com/document/detail/zh/Glossary/gls/gls_0001.html)，引入领域新概念时，需给出必要的解释，并登记在[CANNBot-DSL术语表](../guide/glossary.md)中。

示例：

该接口对输入执行xxx，并将结果写入xxx。

## 函数原型

准确展示公开接口的参数顺序、关键字参数、类型、默认值和返回类型，和代码保持一致。类型使用开发者可见的Python或DSL类型，不使用内部中间表示类型。统一不加`def`关键字和末尾冒号，直接写`函数名(参数) -> 返回类型`。

```python
api_name(
    required_arg: PublicType,
    optional_arg: PublicType | None = None,
) -> ReturnType
```

## 参数说明

固定使用“参数、输入/输出、说明”三列。

- 输入/输出：只使用“输入”“输出”或“输入/输出”；特定模式下会读取原值时，明确写出触发条件。
- 说明：需准确描述参数功能，包括但不限于参数含义/单位/取值范围/默认值/约束信息/可选必选信息等，如果不涉及可删减对应内容。
  - 对于数值类参数：需明确单位、取值范围、默认值、支持的数据类型；若函数原型中已比较明确（如类型标注完整的数值参数），可不强制。
  - 对于数据结构类参数（枚举/类/结构体）：其定义与成员含义须**单独维护一份数据结构类文档**，此处**不得重复罗列数据结构的成员定义**，只须描述参数用途，并附链接指向对应数据结构文档，以避免同一数据结构被多个API使用时产生多个描述源头。
  - 关于可选必选信息：若从函数原型中看不出来，则需要在说明信息中明确。如果可以看出来，则可写可不写，全文保持统一即可。

示例：

| 参数 | 输入/输出 | 说明 |
| --- | --- | --- |
| dst_tile | 输出 | 目的操作数，Tile类型，支持的数据类型为xx，xx，xx。 |
| src_tile | 输入 | 源操作数，Tile类型，支持的数据类型为xx，xx，xx。|
| offset | 输入 | 可选，以列表或元组传入，表示小Tile在大Tile中的相对位置，长度为2，格式为[offset_m, offset_n]，两项均可为整型常量或运行时整型标量表达式，单位为元素个数。<br>- 当源操作数的shape >= 目的操作数的shape时，表示从源操作数的第offset_m行offset_n列开始读，数据的搬运量取自目的操作数的valid_shape。<br>- 当源操作数的shape < 目的操作数的shape时，表示从目的操作数的第offset_m行offset_n列开始写，数据的搬运量取自源操作数的valid_shape。 |

## 返回值说明

明确返回内容和公开类型。通过输出参数返回结果时，说明结果写入哪个参数；存在累加或原地更新时，说明原有数据如何变化。

示例：

有返回值接口：返回xxx，类型为xxx。

无返回值接口：无返回值。结果写入dst。

## 约束说明

只记录影响接口正确使用的限制。每条约束必须明确说明约束对象、触发条件和具体要求。

- 内容定位：体现该接口的**接口级使用约束**或**较通用的约束**；参数级约束（非型号差异）应尽量在参数说明中就近体现，避免信息过于零散。当参数间存在组合限制，参数说明章节难以表述清楚时，可在此处统一说明。
- 约束数量控制：约束过多会影响用户体验，新增约束前应先评估软件是否有优化空间，避免引入不合理约束。
- 其他要求：
  - 不使用“仅适用于支持该能力的场景”“需要相应配置”等含糊表述。
  - 多个参数存在组合限制时，明确列出合法或非法组合。
  - 存在数据依赖时，明确说明发生冲突的访问以及所需的Channel或同步关系。
  - 不重复功能说明和参数说明已经表达的内容。

示例：

- 当xx时，xx必须xx。
